# 0014. The server is one Go binary over SQLite, Postgres or MySQL

> **Status:** Accepted · **Date:** 2026-11-13

## Context

Three things are asked of the server that the current shape cannot give:

- **Private deployment without handing over source.** A company that runs the
  closed edition on its own machines receives whatever the server is made of.
  Today that is readable JavaScript: Next.js output and `node_modules`.
- **More than one database family.** The databases asked for are SQLite, the
  Postgres family (Postgres, and Postgres-derived products such as openGauss
  or KingbaseES) and the MySQL family (MySQL, and MySQL-compatible products
  such as MariaDB, TiDB or OceanBase in MySQL mode). Prisma binds one schema to
  one provider, so three families means three schemas and three migration
  histories. The current schema also uses Postgres-only features:
  `pgcrypto`, a PL/pgSQL `nanoid()` and advisory locks.
- **A server that is cheap to run anywhere.** ADR 0006 made `npx` the
  cheapest start, but on PGlite, which is alpha, about a third as fast as
  Postgres and about 500 MiB per process.

The project is in the Building stage. The server is about 5,000 lines of
TypeScript, and the only clients it cannot update are installed plugins.
Rewriting now costs one rewrite; rewriting after a first private deployment
costs a migration for every customer.

## Decision

**The server becomes one Go binary that serves the API and the web console,
and stores its data in SQLite, Postgres or MySQL, chosen by `DATABASE_URL`.**

- **Go, not Rust.** The hot path is the model gateway, a streaming proxy that
  waits on the provider; the rest is configuration CRUD. Neither needs Rust's
  control over memory, and Go's HTTP, TLS, reverse-proxy and cross-compilation
  support is in its standard library.
- **No cgo** (`CGO_ENABLED=0`), so every platform is built from one machine
  and the binary has no system dependency. SQLite is `modernc.org/sqlite`.
- **The data layer is written once for three dialects**, through `ent` (Go code
  generation, one schema) with Atlas versioned migrations, one directory per
  dialect, all generated from that schema. The schema uses only what all
  three share:
  - ids are generated by the application (a Go nanoid), not by the database;
  - a limit counted under concurrency (sign-in codes, password guesses) takes
    a row lock in a transaction (`SELECT … FOR UPDATE`; on SQLite a write
    transaction, which serialises by itself), not an advisory lock;
  - JSON is stored as JSON (`jsonb` on Postgres, `json` on MySQL, text on
    SQLite) and read only by the application, never queried inside;
  - MySQL tables use `utf8mb4` with a binary collation, so a unique name
    means the same thing on all three;
  - times are UTC.
- **SQLite is the default.** With no `DATABASE_URL`, the binary opens a file
  in its data directory. It replaces PGlite.
- **The web console is a static single-page app** (React and Vite, reusing
  `@dsh-teamwork/ui`), built into the binary with `go:embed`. Next.js leaves
  the server; server components and server actions become calls to the same
  API the plugin uses.
- **Sign-in is rewritten in Go**, with three doors:
  - **Google**, through `github.com/markbates/goth`;
  - **an emailed code**, or a password where `SMTP_URL` is unset, with
    today's rules: the code as an HMAC, scrypt with its parameters stored,
    each limit spent before the comparison;
  - **Feishu**, through goth's `lark` provider, which speaks to
    `open.feishu.cn`. Lark outside China is a later provider.

  goth only runs the OAuth exchange and stores nothing, so every table stays
  in `ent`. The plugin's PKCE code and 30-day Bearer token are unchanged.
  Sessions and tokens stay stateless (JWE under `AUTH_SECRET`, through
  `go-jose`). Auth.js is removed.
- **An account is no longer its email.** `User.authId` is replaced by an
  `identities` table: `(provider, subject)` is unique and points at one user.
  - Google's subject is its `sub`; Feishu's is the `union_id`, which is the
    same across one developer's apps (an `open_id` is not); an emailed code's
    or a password's is the lower-cased email.
  - Accounts merge by email only on an email the door has verified: an
    emailed code, or Google with `email_verified`. A Feishu email is never
    trusted for this, because Feishu does not promise it is verified.
  - A first Feishu sign-in creates an account. To use Feishu with an existing
    account, a person signs in another way and links it from `/account`.
- **One OpenAPI document is the wire contract.** Go server types and the
  console's TypeScript client are generated from it; it replaces the Zod
  schemas in `@dsh-teamwork/shared`. The plugin's restated snapshot shape is
  checked against it.
- **The closed edition is the same binary with `premium/` compiled in.** The
  closed Go packages register themselves at start; the open binary is built
  from the open tree alone. Only the closed binary is ever handed to a
  customer as a file, never as source.
- **Distribution:**
  - **npm**, as `@dsh-teamwork/server`: one small package whose `bin` is a
    JavaScript launcher, and one package per platform (`linux-x64`,
    `linux-arm64`, `darwin-x64`, `darwin-arm64`, `win32-x64`) holding the
    binary, declared as `optionalDependencies` with `os` and `cpu`, so npm
    installs only the one that matches. Node is needed to install, not to run.
    No `postinstall` download, which `--ignore-scripts`, proxies and offline
    networks break.
  - The same binaries as release downloads, and a container image for
    `compose.yaml`.

## Consequences

- **`npx @dsh-teamwork/server` still works**, and the server it starts needs
  neither Node nor a database server.
- **Three dialects are three migration histories and three CI runs.** Every
  suite that touches the database runs on SQLite, Postgres 16 and MySQL 8, and
  the drift check runs per dialect. A product in a family (openGauss, TiDB, …)
  is supported once that suite passes against it, not by assumption.
- **A compiled binary raises the cost of reading the closed edition; it does
  not prevent it.** Symbols are stripped, but a determined reader can still
  decompile Go. What protects the closed edition is the licence, the contract,
  and keeping what must not leave on the hosted service.
- **Everything built on Next.js, Prisma and Auth.js is rewritten**: the API,
  `lib/team.ts`, the gateway, sign-in, the console pages, `packages/db`, the
  server half of `packages/shared`, and `premium/apps/manage`. Their tests are
  rewritten with them, sign-in and the gateway's network rule first, because
  they are security boundaries.
- **This repository leaves seed's stack.** The Prisma, NextAuth, Vitest and
  Railway sections of `CLAUDE.md`, the gate and the sibling tooling no longer
  apply and are rewritten; the Documentation section is still kept verbatim.
- **SQLite holds one writer at a time**, which fits one team or a small
  company; a larger deployment sets `DATABASE_URL` to Postgres or MySQL.
  Moving between databases is an export and import the binary provides, since
  three dialects rule out `pg_dump` as the documented path.
- **The plugin's wire does not change in this rewrite**: `/api/configs`,
  `/api/auth/plugin/token` and the gateway keep their shapes, so an installed
  plugin keeps working against the Go server. Plugin tokens issued by the
  Node server stop working, and members sign in again once.
- **Supersedes** ADR 0006's database decision (PGlite, and
  ruling out SQLite) and its packaging. Its sign-in, provider-key and
  network decisions carry over unchanged. ADR 0002 (the platform is built
  from seed) stops describing the stack.
- **A second door no longer merges by itself.** A person who signed in with a
  password and then with Feishu has two accounts until they link them. That
  is the price of never trusting an unverified email.
- **Ruled out:**
  - **An identity service beside the binary** (Casdoor, Ory, Zitadel): a
    second process, with its own database and ORM.
  - **goth's `wechat` provider as it is**: it invents `openid@wechat.com` as
    the email, which would merge strangers' accounts under the old rule.
    WeChat, WeCom and DingTalk wait until a team asks for them.
  - **Rust**, for a cost in development time with no gain the gateway can
    use.
  - **Prisma with three schemas**, three histories and every raw query
    written three times, while the JavaScript stays readable.
  - **Next.js kept in front of a Go API**, two runtimes in every deployment.
  - **SQLite through cgo**, which ties every build to a C toolchain per
    platform.
  - **A `postinstall` download of the binary.**

## Order of work

The unknowns that could change this decision are answered first, by
experiments thrown away afterwards:

1. **Three dialects from one schema.** Today's tables and `identities` in
   `ent`, migrations for all three, and the concurrent sign-in-code test
   passing on SQLite, Postgres 16 and MySQL 8.
2. **The gateway.** Streaming parity with today's gateway on the same
   requests, and its latency and memory against the Node gateway on one
   fixture.
3. **Packaging.** A hello-world binary published to a scratch npm scope and
   run with `npx` on Linux, macOS and Windows.

Then one vertical slice, end to end, against an unchanged plugin: a password
sign-in, `/teamwork login`, `/api/configs` and one call through the gateway.
Then the team API and the console. Then `premium/`. The Node server is deleted
in the commit where the Go server serves everything it did.
